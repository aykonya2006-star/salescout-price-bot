# SaleScout Price Bot

Мини-версия прайс-бота по [официальному заданию SaleScout](https://github.com/SaleScout-me/salescout-intern-task). Рассчитывает цены по конкурентам и показывает сравнение «было / стало» через реальные запросы React → Express.

## Возможности

- Именованный экспорт `calculatePrice(product: Product): PriceResult` в исходном `src/pricing.ts`.
- `POST /reprice`, runtime-валидация, JSON-ошибки, сохранение порядка и поддержка пустого массива.
- Неизменённые официальные демоданные, цены в тенге, русские причины, разница и сводка.
- Повторный расчёт, очистка/загрузка каталога, загрузка, ошибки сети/API и таймаут 15 секунд.
- Адаптивная страница, прокрутка таблицы, клавиатурный фокус и объявления состояния для скринридеров.
- 78 тестов алгоритма, API и клиента; 100% покрытия `calculatePrice`.

## Стек и окружение

TypeScript, Express 5, React 19, Vite 8, Vitest 4, Supertest, `tsx` для запуска сервера.

Нужны **Node.js 20.19.0+ в ветке 20** либо **Node.js 22.12.0+**, и npm. Минимальная версия уточнена из-за требований Vite 8. Vitest 4 выбран для поддержки Node.js 20. Lockfile фиксирует проверенные зависимости. Проект проверен на Node.js 20.19.0 и 24.16.0.

## Установка и запуск

Из корня проекта:

```bash
npm install
```

Backend в первом терминале:

```bash
npm run dev:server
```

API: `http://127.0.0.1:3001`. Сервер перезапускается при изменении файлов. Запуск без наблюдения: `npm run start:server`.

Frontend во втором терминале:

```bash
npm run dev
```

Откройте **http://127.0.0.1:5173** и нажмите **«Рассчитать цены»**. Vite проксирует `/reprice` на API, отдельный CORS не нужен. `strictPort` предотвращает незаметный переход на другой порт.

Если Windows PowerShell запрещает запуск `npm.ps1`, используйте `npm.cmd`, например `npm.cmd install` и `npm.cmd run dev`. Менять политику выполнения не требуется.

Для другого порта в PowerShell задайте `$env:PORT = '3002'` перед запуском backend, а во frontend-терминале — `$env:API_TARGET = 'http://127.0.0.1:3002'` перед запуском `dev` или `preview`. По умолчанию `.env` не нужен.

## API

`POST /reprice`, `Content-Type: application/json`, тело — `Product[]`:

```json
[
  {
    "sku": "IPH15-128-BLK",
    "name": "Apple iPhone 15 128Gb черный",
    "myPrice": 389990,
    "minPrice": 370000,
    "maxPrice": 420000,
    "step": 10,
    "competitors": [
      { "seller": "TechnoMarket", "price": 384990, "inStock": true },
      { "seller": "GadgetKZ", "price": 379990, "inStock": false }
    ]
  }
]
```

Ответ `200`:

```json
[
  {
    "sku": "IPH15-128-BLK",
    "oldPrice": 389990,
    "newPrice": 384980,
    "reason": "UNDERCUT"
  }
]
```

Проверка всего официального набора (Bash):

```bash
curl -i -X POST http://127.0.0.1:3001/reprice \
  -H 'Content-Type: application/json' \
  --data-binary @data/products.json
```

Windows PowerShell:

```powershell
curl.exe -i -X POST http://127.0.0.1:3001/reprice -H "Content-Type: application/json" --data-binary "@data/products.json"
```

Результат совпадает с `data/expected.json`. Тело `[]` возвращает `200` и `[]`.

| Статус | Условие                                                                       |
| ------ | ----------------------------------------------------------------------------- |
| 200    | Валидный массив, в том числе пустой                                           |
| 400    | Повреждённый JSON, тело не-массив, отсутствующее JSON-тело или неверный товар |
| 413    | Тело больше 1 МБ                                                              |
| 415    | Неверный Content-Type или неподдерживаемая кодировка                          |
| 404    | Неизвестный маршрут                                                           |
| 500    | Непредвиденная внутренняя ошибка                                              |

Пример ошибки: `{ "error": "Некорректный JSON в теле запроса." }`. При неверном товаре сообщается индекс с нуля. Запрос отклоняется целиком, частичных результатов нет.

Строки проверяются по типу: пустые строки и повторяющиеся SKU допустимы. Все числа должны быть конечными и неотрицательными; границы — целыми, `minPrice <= maxPrice`. `myPrice`, `step` и цены конкурентов могут быть дробными. Неверные поля конкурента отклоняются даже при `inStock: false`.

## Алгоритм

1. Учитываем только `inStock === true`, находим минимальную цену `best`.
2. Нет доступных конкурентов → `maxPrice`, `NO_COMPETITORS`.
3. Иначе `candidate = Math.floor(best - step)`.
4. `candidate < minPrice` → `minPrice`, `AT_MIN`.
5. `candidate > maxPrice` → `maxPrice`, `AT_MAX`.
6. Иначе → `candidate`, `UNDERCUT`, включая точное совпадение с границами.

`myPrice` не влияет на расчёт: он без изменений возвращается в `oldPrice`. SKU также сохраняется. Функция не меняет входные данные и не выполняет I/O; она полагается на гарантии спецификации. Валидация находится на HTTP-границе.

Пример: `349999.9 - 0.5 = 349999.4`, после `Math.floor` — `349999`. Отрицательный кандидат округляется вниз и затем ограничивается `minPrice`.

## Архитектурные решения

Алгоритм, транспорт и отображение разделены без дополнительных сервисных слоёв. `app.ts` не открывает порт при импорте: его удобно тестировать через Supertest. Контроллер валидирует запрос и вызывает `map(calculatePrice)`. Поиск минимума — O(n) по числу конкурентов, дополнительная память — O(1); сортировка и spread не нужны.

Frontend импортирует из `src` только типы. Результаты сопоставляются товарам **по индексу**, чтобы повторяющиеся SKU не теряли строки. Клиент проверяет формат ответа, порядок SKU и `oldPrice`. Изменение каталога во время запроса заблокировано. После ошибки устаревшие результаты не показываются.

## Ограничения и публикация

Это локальная демонстрация без базы данных, авторизации, интеграции с Kaspi и применения цен в магазине. Повторный расчёт использует исходные данные. Сервер слушает loopback; лимит запроса — 1 МБ. Статический frontend для размещения потребует отдельного Express-сервера и reverse proxy `/reprice` на том же origin: proxy Vite не входит в сборку. Арифметика использует JavaScript `number` и `Math.floor`, как требует спецификация.

Скрытые тесты недоступны; гарантировать их прохождение нельзя. По выполненным проверкам существенных дефектов не осталось.

Локальные коммиты сохранены по этапам. Для публикации владельцем:

```bash
git status
git log --oneline -5
git remote -v
# Если origin отсутствует, добавьте адрес своего пустого репозитория:
git remote add origin https://github.com/YOUR_LOGIN/salescout-price-bot.git
# Если origin уже указывает на ваш репозиторий, добавлять его повторно не нужно.
git push -u origin main
```

Перед push проверьте адрес `origin`; при необходимости используйте `git remote set-url origin ...`. Задание требует свой публичный репозиторий и ссылку в сопроводительном письме на hh.kz. Публикация агентом не выполнялась.
