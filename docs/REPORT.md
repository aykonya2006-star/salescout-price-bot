# Итоговый отчёт — SaleScout Price Bot

Дата проверки: 14 октября 2026 года.

Проект реализован в существующем репозитории по [официальному заданию SaleScout](https://github.com/SaleScout-me/salescout-intern-task). Контракт `src/pricing.ts` сохранён. Исходные типы и официальные JSON-данные не менялись по содержанию. Добавлены чистый алгоритм, Express API, React/Vite dashboard, тесты и документация.

## Выполненные требования

- Именованный экспорт `calculatePrice(product: Product): PriceResult` на исходном пути, без I/O и мутаций.
- Фильтрация строго по `inStock === true`, минимум, `Math.floor(best - step)`, все четыре причины.
- Строгие сравнения границ: точное совпадение возвращает `UNDERCUT`.
- Неизменённые `sku` и `oldPrice`; текущая цена не влияет на расчёт.
- `POST /reprice`: JSON-массив, порядок результатов, пустой массив, 400 для неверного тела.
- Runtime-валидация и понятные JSON-ошибки, лимит 1 МБ, обработка неподдерживаемой кодировки.
- React + TypeScript + Vite, официальный демокаталог и реальный HTTP-запрос.
- SKU, название, старая/новая цена, причина, изменение цены в тенге.
- Загрузка, сетевые/API-ошибки, повтор, пустое состояние и мобильная раскладка.
- Vitest-тесты алгоритма, API и клиента, команды запуска и сборки, lockfile и `.gitignore`.
- Локальная история коммитов по этапам; удалённая публикация не выполнялась.
- Подготовка к собеседованию: [INTERVIEW.md](INTERVIEW.md), 15 вопросов и три изменения требований.

## Дополнительные улучшения

Минимум ищется за один проход с O(1) дополнительной памятью, без ограничения spread-аргументов. Есть тест на 200 000 конкурентов. Клиент ограничивает ожидание 15 секундами и проверяет не только HTTP-статус, но и JSON-ответ, порядок SKU и исходные цены. Повторяющиеся SKU поддерживаются без потери строк.

Во время запроса кнопки изменения каталога заблокированы. После ошибки устаревшие результаты убираются. Добавлены сводка, время расчёта, текстовые русские причины, пояснения правил, фокус с клавиатуры, `aria-live`, поддержка reduced motion и подсказка прокрутки таблицы на телефоне. CSS и шрифты не требуют внешних ресурсов.

## Найденные и исправленные проблемы

1. Стартовая `calculatePrice` бросала `Not implemented`; реализован алгоритм из спецификации.
2. `npm test` был заглушкой с кодом выхода 1; добавлен Vitest и реальные тесты.
3. Backend и frontend отсутствовали; добавлены сервер, proxy, интерфейс и работающий HTTP-поток.
4. PowerShell блокировал `npm.ps1`; проверки и инструкции используют `npm.cmd`, без изменения системной политики.
5. Две строки параметризованных тестов клиента передавали массив как набор аргументов. Тестовые случаи обёрнуты в `{ body }`; бизнес-правила не менялись для исправления тестов.
6. При review выявлено, что unsupported charset/content-encoding мог попасть в общий ответ 500. Теперь возвращается 415; оба случая покрыты интеграционными тестами.
7. После просмотра скриншотов увеличены мелкие подписи и контраст, добавлена мобильная подсказка прокрутки.

## Файлы и локальный запуск

Полное дерево файлов и архитектура находятся в [README.md](../README.md#структура). Главное разделение: `src/` — алгоритм/типы; `server/` — HTTP/валидация; `frontend/` — React/клиент/стили; `tests/` — проверки; `docs/` — подготовка и отчёт.

После установки зависимостей запустите в двух терминалах:

```powershell
# Терминал 1
npm.cmd run dev:server
```

```powershell
# Терминал 2
npm.cmd run dev
```

Страница: http://127.0.0.1:5173. Требуется Node.js 20.19.0+ в ветке 20 либо 22.12.0+.
